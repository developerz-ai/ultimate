# Changelog

All notable changes to Ultimate. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Framework packages version in **lockstep** — a release bumps every package to the same version, in one commit, under one tag. Declare `@ultimat3/*` at `^<version>`, as `x new` writes, and let `bun.lock` pin the build; keep every one on the same version, since a mixed-version install is a combination nobody tested. See [PUBLISHING.md](PUBLISHING.md).

Semver applies from 1.0.0. A breaking change to a documented API needs a major — [Upgrading](https://github.com/developerz-ai/ultimate/wiki/Upgrading) says what "documented API" covers. From 23.0.0 on, each `BREAKING —` line names its migration as `(#N)` straight after the dash — row N of that major's `Entry by entry` table in Upgrading — and `bun run changelog-check` refuses a line without one (`X_DOC_MIGRATION_UNPAIRED`).

**Majors 1 through 30 were the pre-stability line**: shipped from 2026-08 under semver, often weeks apart, each with its edit in [Upgrading](https://github.com/developerz-ai/ultimate/wiki/Upgrading). v31 is the stable line: from it, at most one major every 90 days (`X_RELEASE_MAJOR_WINDOW`), breaking changes wait on `next` (`X_BREAKING_ON_MAIN`), and the previous major gets security fixes for six months — [Stability](https://github.com/developerz-ai/ultimate/wiki/Stability).

## [Unreleased]

### Added

- `@ultimat3/db`: `slowStatementLog({ thresholdMs })` — one grep-able `db.statement.slow` warn line per statement shape per 10 s, with the request id and no bind values. `x serve` installs it at `SLOW_STATEMENT_THRESHOLD_MS` (500 ms) in production, off elsewhere.
- `@ultimat3/db`: `tableStorage(table, { fillfactor, unlogged })` and `createTableDdl(storage, columns)` — a framework table declares its storage parameters; the framework-schema apply re-applies them, and `x db migrate` reports one changed by hand as `changed-table-storage`, with the `alter` that undoes it.
- `@ultimat3/db`: `X_MIGRATION_LOCK_HEAVY` — a migration newer than `20261113000000` that runs `set not null` with no validated check before it, or `create index` without `concurrently` on a table it did not create, is refused by `x verify`'s drift step. Fix: the two-step form; `-- lock-heavy: true` admits a deliberate one.
- `@ultimat3/db`: an index description renders an expression key, a direction per key (`orders`), `include` and `operatorClass: 'gin_trgm_ops'`; `x db gen` records and re-reads each and creates `pg_trgm` before the first trigram index. Drift compares each. An entity's `indexes:` does not declare these yet.
- `@ultimat3/http`: `slowRequestMs` (default 1,000; `0` = off) — a request over it logs one `http.request.slow` warn line: route, status, total, the gate/handler/db/render/cache split, the request id.
- `@ultimat3/http`: every 4xx is counted in `http_refusals_total{code}`.
- `@ultimat3/http`: `Server-Timing` breaks a request into gate, handler, db, render and cache under `x dev`; production sends the total only.
- `@ultimat3/http`: `shedLagMs` — while event-loop lag p99 exceeds it, `admit` sheds `X_OVERLOADED` (503, `retry-after: 1`). Off by default (`0`).

### Changed

- `@ultimat3/core`: `addressNetwork` caches up to 4,096 addresses (LRU), so http rate limiting, auth's ip key and realtime's subscription book stop re-parsing a returning caller's address.
- `@ultimat3/http`: a refused request (404/401/403/429) no longer renders its error's stack — `ErrorFacts.stack` is computed on first read — and the per-request floor allocates less: no `AbortSignal.any`, `vary` merged without a `Set`, no `URLSearchParams` without a query string, security headers from one precomputed list. As of 2026-11, `scripts/bench/http-pipeline.bench.ts` (in-process, Bun 1.4.4, 30,000 requests): hello 91.8 µs, 404 132.3 µs.
- `@ultimat3/http`: a response is zstd-coded when the client offers it, otherwise gzip (RFC 9110 weights); brotli is left to build-time precompression.
- `@ultimat3/http`: a public answer with a strong ETag is compressed once per process (bounded LRU, 512 entries / 16 MiB), not on every hit.
- `@ultimat3/http`: `x_rate_limit` is `unlogged` at `fillfactor = 70`, and a take no longer writes `updated_at`: a take writes no WAL (2 records → 0; HOT share 0.849 → 1.000 over 5,000 takes). After a Postgres crash or on a promoted standby every bucket comes back full; `x_auth_lockouts` stays logged.
- `@ultimat3/http`: a routine refusal (401/403/429) logs `info` once per route per minute, then `debug`.
- `@ultimat3/http`: a `text/*` request body is decoded by its declared `charset` (UTF-8 when none); an unknown label is `X_BODY_INVALID`. JSON and forms stay UTF-8.
- `@ultimat3/db`: `x db gen` builds an index on an existing table `concurrently` by default, in a `-- transaction: false` follow-up file. `concurrently: false`, or a partitioned parent, writes a plain build marked `-- lock-heavy: true`.
- `@ultimat3/db`: a request waiting for a pool slot leaves the queue when its deadline passes, and a read leaves when its caller hangs up: dead waiters no longer hold their place until `acquireTimeoutMs`.
- `@ultimat3/storage`: a part URL on the local and memory disks signs its exact length (`x-len`, `v3-part`); a shorter part is `X_STORAGE_URL_INVALID`, as s3 refuses it. A part URL minted before the upgrade is refused: request it again.

### Fixed

- `@ultimat3/http`: a 304 carries the same validator form as the 200 it revalidates (RFC 9110 §15.4.5).
- `@ultimat3/db`: on a pinned connection, `ROLLBACK TO SAVEPOINT`, `RESET statement_timeout` / `RESET ALL` and `SET statement_timeout TO DEFAULT` restore the statement bound the unanswered-statement sweep checks, so it no longer misfires or retires the pool on a stale bound.
- `@ultimat3/cli`: a boot refused by its OTLP exporter no longer leaves the metric and statement subscribers installed; production and `x dev` boots install the request timings `http.request.slow` and dev `Server-Timing` read.

## Older releases

`10.0.0` and everything before it are **in git history, not in this file**. No length cap is
enforced: trimming is a deliberate edit that deletes the oldest `## X.Y.Z` sections, because a
changelog nobody scrolls to the bottom of is a changelog nobody reads, and every deleted line is
one `git show` away.

| Want | Run |
|---|---|
| one past release's section | `git show v10.0.0:CHANGELOG.md` — or any tag; every release from 1.0.0 on is tagged |
| when a line was written, and by whom | `git log -p --follow -- CHANGELOG.md` |
| the whole file as it stood at the last full release | `git show v13.0.0:CHANGELOG.md` |
| what a major broke, without git | [`wiki/Upgrading.md`](https://github.com/developerz-ai/ultimate/wiki/Upgrading) — it walks **every** major, oldest first, and is deliberately NOT truncated |

**The upgrade guide is the one that has to stay complete**, and it does: a reader upgrading across
four majors needs every walkthrough in order, where a reader of this file wants the last release.
Two documents, two jobs — `bun run changelog-check` reads the oldest `## X.Y.Z` heading still here
as the retention boundary and stops demanding a section below it, so trimming this file again is
deleting sections and nothing else.
