# @postly/db

Entities + migrations + cache tags + seeds. Nothing else.

## Boundary

| May import | Must never |
|---|---|
| `@postly/domain`, `@ultimat3/entity`, `@ultimat3/cache` | `@postly/core`, any app, `@ultimat3/http` |
| — | business logic, policy checks, mail, jobs |

## Files

| File | Owns |
|---|---|
| `src/schema/*.ts` | one entity each |
| `src/client.ts` | the `db` handle built from the entity set |
| `src/tags.ts` | the cache-tag graph (`tag.post`, `tag.feed`, …) |
| `src/errors.ts` | `X_DB_TENANT_MISSING` |
| `migrations/*.sql` | GENERATED by `x db gen` — never edited |
| `seeds/dev.ts` | the deterministic dev + test fixture graph |

## Commands

| Task | Command |
|---|---|
| generate a migration | `x db gen "<message>"` |
| apply | `x db apply` |
| seed | `x db seed dev` |
| inspect | `x db describe --json` (or the `schema.describe` MCP tool) |
| typecheck | `bun run --filter @postly/db typecheck` |

## Conventions

- `NOT NULL` is the default. `.nullable()` opts out and must be justified in a comment.
- Tenant column is `orgId()` on every non-catalog table, first in every composite index.
- Invariants use the fluent builder so one declaration becomes both a `CHECK` and a runtime guard.
- Denormalised counters (`posts.likeCount`) are maintained by the owning mutator, never by a
  trigger — a trigger is invisible to the live-query matcher.

## Gotchas

- Editing an entity without running `x db gen` fails `x verify` with `X_DB_DRIFT`.
- Adding a column that live queries select changes the replication payload; re-run `x test live`.
- `likes` has no surrogate key on purpose: the composite primary key is what makes a replayed
  offline `toggleLike` idempotent.
