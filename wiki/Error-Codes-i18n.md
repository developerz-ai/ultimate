# Error codes: `@ultimat3/i18n`

Part of [Error codes](Error-Codes): every code `@ultimat3/i18n` registers. `x errors explain <CODE> --json` prints the same row.

| Code | Means | Typical cause | Fix |
|---|---|---|---|
| `X_CATALOG_INVALID` | a catalog entry is malformed | bad interpolation or a non-string value | `x i18n check --json` |
| `X_CATALOG_MISSING_KEYS` | a catalog is missing keys used in source | a new `t()`, mail or push key with no translation, a key `en` defines that this locale lacks, or a key a mounted admin derives (`admin.<table>.field.<column>`; no source file spells one). The sync writes the file nested — a hand-added dotted key is `X_CATALOG_INVALID`. For a key source names it writes `⟦key⟧` in the default locale and `⟦the default locale's string⟧` in any other; for a key a mounted admin derives, the generated label in the default locale (a real string, accepted by the gate) and that label inside `⟦…⟧` in any other. The CLI's findings say so per locale and key kind, and `x errors explain` quotes the same placeholder rule (`As of 2026-11-19`) | `x i18n sync <locale>` |
| `X_CATALOG_UNREGISTERED` | a shipped catalog never reached the runtime registry | `defineCatalogs()` in a module the boot scan never imports, or one that throws on import — every string renders `⟦key⟧` while `x verify` is green. When two copies of `@ultimat3/i18n` are installed the cause says so instead, and the fix is the install's (`X_PACKAGE_DUPLICATED`, reported beside it): the call is where it should be and registered into the copy the CLI does not read | move the `defineCatalogs()` call into `packages/i18n/src/index.ts` and read strings through its `useT()`; `x i18n check --json` re-checks |
| `X_I18N_FAMILY_INCOMPLETE` | a select or ordinal family has no _other | a catalog defines <key>_select_<value> or <key>_ordinal_<category> keys and no <key>_select_other or <key>_ordinal_other, so a value the family does not name renders the loud miss | `x i18n check --json` — then add <key>_select_other (or <key>_ordinal_other) to the catalog it names |
| `X_LOCALE_UNSUPPORTED` | locale is not in the supported set | a URL or header requesting an unconfigured locale | `x i18n add <locale>` |
