## 30.0.0 - 2026-11-07

### Highlights

- One major for the whole of plan 101: every breaking change below lands here once, each with its edit in [Upgrading](https://github.com/developerz-ai/ultimate/wiki/Upgrading).
- Writes that outlive their caller roll back, a closed transaction refuses a statement, a cross-tenant reference is a composite key Postgres refuses, and TOTP codes stay spent across replicas.
- `x upgrade` ships, one major per run, under a stability promise: one major per 90 days, a support window, deprecation before removal ([Stability](https://github.com/developerz-ai/ultimate/wiki/Stability)).
- `.contract()` calls every handler with generated legal input, and the gate's new `exercise` step calls every action, query and job with no test written, `errors:` closes the 4xx codes a caller may branch on, and an action or a read serves a resource-shaped URL: `http: { path: '/orders/:id/refund', method: 'PATCH' }`.
- A list is a URL: `listUrl` and a link-mode `DataTable` page with scripting off, keyed rows survive a live update, and `refresh()` keeps the visitor's focus.

### Security

- Breaking entries (#6), (#7), (#8), (#16), (#17), (#23), (#26), (#27), (#28), (#29), (#36), (#72) and (#74) are security fixes; each is stated under Changed, where its migration key is.
- `@ultimat3/jobs`: a plain `handle.enqueue(input)` / `enqueueMany` stamps the row with the tenant the payload names. Org B's enqueue of a key org A held (`invoice:1`) deduped onto A's job and returned A's id, and `perTenant` / `ratePerTenant` counted every plain enqueue as tenantless.
- `@ultimat3/auth`: client-id metadata-document fetches on `/oauth/{token,revoke,introspect,device}` are metered per caller address (429 `temporarily_unavailable` past the limit), and the metadata cache evicts oldest-first instead of clearing at 1,000. An unauthenticated caller cycling URL paths made one outbound fetch per request.
- `@ultimat3/admin`: `adminCreate` / `adminUpdate` (and so `callAdminTool`) drop `readOnly` and `hidden` fields from direct input, as the form and the MCP schema already did. The deployed demo reads only its `__Host-` session cookie over https.
- `mcpConfirmations`: an approval no longer crosses orgs. The open confirmation is keyed by actor, org, tool and input digest in both stores, and the gate refuses a row of another org (`X_MCP_CONFIRMATION_EVIDENCE_INVALID`, `reason: 'org'`, a new member of `McpEvidenceFailure`). An actor id shared across orgs ran a call in one org that only another had approved. The framework schema replaces `x_mcp_confirmations_open_idx` with `x_mcp_confirmations_open_org_idx`.
- `x build --target static` reads `sitemap.xml` routes' `prerender()` and `llms.txt` pages' `load` through an in-process API that authenticates nobody. They ran as the measurement actor, so a public file could carry rows only that actor reads.
- `pushRegister()` keeps at most `PUSH_DEVICES_PER_ACTOR` (20) devices per person, evicting the oldest, so one account cannot make every notification it receives a fan-out of thousands of provider requests.
- `auth`: a spent TOTP code stays spent across replicas. A framework boot installs the new `postgresTotpReplayGuard` over `x_totp_steps`. Before, the same six digits signed in once per replica, and a guard answering asynchronously refused every right code.
- **A foreign `Host` cannot name itself in a stored `isr` page.** With no declared origin the store key carries the request's origin (`isrKey(url, locale, origin?)`, the reserved `__x_origin` parameter), so each host sees its own canonical and `og:url`. With a declared http or https origin `load` is now handed `url` at that origin. With none, a process stores pages for 16 request origins and answers any other `Host` uncached, evicting nothing. Entries re-render once.
- `@ultimat3/realtime`: with `allowedOrigins` or `APP_URL` declared, a websocket upgrade from an unlisted origin is refused whatever `sec-fetch-site` it carries. `same-origin` and `none` were admitted beside the declared list, so a sibling host pointed at the node passed with a `Domain=` cookie riding. `x dev`'s `admitReachedOrigin` is unchanged.
- `@ultimat3/core`: `proveSameOrigin` never takes `Origin: null` as proof, whatever `selfOrigins` or `listed` answers. That covers `checkCsrf`, the `/_x` dashboard and the sync upgrade. `allowedOrigins: ['localhost:3000']` parses to the origin `null`, which admitted every sandboxed iframe.
- `@ultimat3/core`: `classifyAddress` reads the IPv4 inside 6to4 (`2002::/16`) and IPv4-translated (`::ffff:0:0/96`) addresses. Teredo (`2001::/32`) classes `private`. `2001::/23`, `3fff::/20`, `192.88.99.0/24` and everything outside `2000::/3` class `reserved`. All of these read `public` before, so webhook delivery, the scraping pin, `hostDecision` and the push screen now refuse them.
- `@ultimat3/core`: added `peerAddressClass`, the class of an address as a caller or a local name. A transit form spelling an inward IPv4 (`64:ff9b::7f00:1`, `2002:7f00:1::`, `::127.0.0.1`, `::ffff:0:7f00:1`) answers `reserved`, never `loopback` or `private`. `healthDetailPeers`, the `/_x` loopback `Host` check, `X_CSRF_BLOCKED`'s local hint and the test seal now ask it.
- An s3 upload grant binds its size at the provider: the URL signs `content-length`, so a browser holding it cannot store any other length (#36).
- Private adopter names are out of the public tree: source comments, docs, wiki pages and test fixtures say "one adopter" (or use `example.com` fixtures), and every figure stays as it was. `scripts/private-names.ts` (`bun run private-names`, `X_PRIVATE_NAME`, on the `boundaries` step) refuses any line or path carrying an entry of the `ULTIMATE_PRIVATE_NAMES` CI secret, in tracked files and in untracked files git does not ignore, and prints the file:line and the entry's index, never the name. With the secret unset it prints a skip note, except on a push to `main`, where a missing secret is red (`X_PRIVATE_NAMES_UNSET`). CI hands the secret only to the `x verify` step of the gate part that runs `boundaries`.
- `@ultimat3/flags`: the example subject kind in the `X_FLAG_SUBJECT_REQUIRED` fix comment and tests is `payments-provider`.
- `outbound()` never follows a redirect unless asked, screens every hop after the first even under `dial: 'named'`, carries only `accept`, `content-type` and `user-agent` across origins, and writes a path into causes, `meta` and logs as its first segment plus the length of the rest.
- `@ultimat3/admin`: `/admin/audit` refuses any parameter it does not read, `?org=` included, with a 400 (`X_ADMIN_FILTER_INVALID`). The tenant stays the actor's. The screen re-checks every entry an app's own `AuditLog` returns against the query, tenant included, so a log that ignores a field can only draw a shorter page, never another org's entry.
- `@ultimat3/mcp`: a cross-origin `Origin` on `POST /mcp` is refused before the bearer token is read, so a token in a hostile page's hands decides nothing (#72). `x mcp serve` refuses a DNS-rebound name by its Host (421, #74); on an app's `/mcp` a rebound page is same-origin by construction, and `x new`'s development token stays honoured only with no `Origin` at all. A resource not found stays one answer for hidden and absent on both eras (`-32601` legacy, `-32602` modern, no `data`).

### Changed

- **BREAKING — (#1) `@ultimat3/core`: `close`-phase `onShutdown` hooks run last-registered first.** `accept` and `inflight` stay in registration order. A span ended by a worker's or an app's `close` hook now reaches the collector; the flush used to run first in that phase.
- **BREAKING — (#2) `@ultimat3/core`: `retry()` stops on the ambient `ctx.signal`,** its budget clamped to what is left of `ctx.deadlineAt`, and takes `deps` as optional, `sleep` included. `runToCompletion(fn)` is the way to outlive a caller. Outside a request context nothing changes.
- **BREAKING — (#3) A write past `requestTimeoutMs` or a job's cancellation rolls back** instead of landing after the caller was answered: `withTransaction`, an entity write on either driver and `enqueue` rethrow the signal's coded reason. A client hang-up is uncoded and changes nothing. A keyed `idempotent` action runs to its end, on a fresh signal, inside a `withTransaction` or not, so its replay answers success, up to a hard ceiling of twice `requestTimeoutMs` (60 s by default). Past it the handler is aborted and the key replays `X_IDEMPOTENCY_RUN_CEILING`.
- **BREAKING — (#4) A statement on a `DbTx` whose scope already ended is `X_DB_TRANSACTION_CLOSED`** instead of an autocommit on the pool.
- **BREAKING — (#5) `x db gen` refuses to drop a column not retired first (`X_MIGRATION_ROLLING_UNSAFE`).** A drop takes two releases: `entity('<t>', { retired: ['<c>'] })` and `x db gen "retire <c>"`, deploy, then remove it from `retired` and `x db gen "drop <c>" --allow-destructive`. `--rolling-unsafe` is for an app that stops before it starts.
- **BREAKING — (#6) `promoteAttachment` sniffs a 64 KiB head window before it moves an object (S4).** A provider's presigned PUT signs `host` alone, so an uploader could store any bytes under any type and promotion only read the size. The URL stays valid after the sniff, so the copy names the revision judged and is checked after it lands: another size, or bytes that fail the same sniff, are refused and deleted. The claims that the signature covered the content type are corrected, and a test pins what it signs.
- **BREAKING — (#7) Leading whitespace no longer hides markup from the sniff (S7).** 512 whitespace bytes before XHTML, HTML or SVG read as `text/plain`, and XML through `application/xml` was accepted. Trimmed before it is cut; over 4,096 B of leading whitespace is refused on every path.
- **BREAKING — (#8) A `references()` with both ends tenant-scoped is a composite key,** `(tenant, column) -> target (tenant, key)`: a row pointing into another tenant is refused by the database with `X_DB_FOREIGN_KEY_VIOLATION`, the code and the text of a dangling id, so no existence oracle. Reproduced 2026-11-02 as accepted on both drivers. The memory driver refuses a target found under another tenant and still accepts one not found. A self-reference is composite too; an edge to an untenanted root stays plain. `references(() => x.id, { crossTenant: '<reason>' })` is the escape, blank or on an ineligible edge refused.
- **BREAKING — (#9) `@ultimat3/entity`: `update`, `updateWhere` and `transition` validate the named columns** with `insert`'s issues, before the statement, on both drivers.
- **BREAKING — (#10) `@ultimat3/entity`: `orderBy` on a `json`, `bytes` or array column is refused when the plan is built** (`X_INVARIANT_VIOLATED`), at any row count.
- **BREAKING — (#11) Data loss: `db.x.upsertAll` reset every unnamed column on a collision** (`label` to its default, `note` to null, `createdAt` to now), because `$parse` filled them first; `seed.upsert` likewise. A collision now overwrites only what the caller's rows named, plus `onUpdateNow()` columns, and an uneven batch through `db.*` is refused (`X_INVARIANT_VIOLATED`), as documented. New optional `UpsertArgs.overwrites`.
- **BREAKING — (#12) `upsertAll` on a hand-held repository:** a property present with `undefined` no longer overwrites the stored column with its default. Beside a row writing a value it is an uneven batch (`X_INVARIANT_VIOLATED`), and with no row writing a value it leaves the set list.
- **BREAKING — (#13) `insertAll` / `upsertAll` past Postgres's bind ceiling are all or nothing:** the chunks run in one transaction (a savepoint inside an open `withTransaction`). A failing chunk propagates `X_DB_UNIQUE_VIOLATION` and leaves no row of the batch; one chunk stays one autocommit statement with no `BEGIN`.
- **BREAKING — (#14) JS-only invariants judge what an updating upsert merged,** on Postgres as in memory, and judge a soft delete in both (`delete`, `deleteWhere`, all or nothing, bounded by `MAX_ASSERTED_ROWS`).
- **BREAKING — (#15) `/media` on a shared key no longer answers `public, max-age=31536000, immutable`.** Every `/media` answer is `private, max-age=0` plus an `etag`, with 304 and `Range:`.
- **BREAKING — (#16) `auth`: `TotpReplayGuard` drops `isUsed` and `remember` for `claim`.** `claim(subject, step, at): Promise<boolean>` is one atomic method; `completeMfa` awaits it after the code verified. `MemoryTotpReplayGuard` keeps `isUsed`, for tests. `defineAuth` refuses a `totpReplay` with no `claim` function (`X_CONFIG_INVALID`). A guard that rejects propagates from `completeMfa` and the guess is not counted.
- **BREAKING — (#17) A tool in `mcpConfirmations({ tools })` waits for a person from `agent({ tools })`.** The gate wrapped MCP tools only, so the same call that answered `X_MCP_CONFIRMATION_PENDING` over `tools/call` ran from `agent({ tools })` with nobody asked. The adapter now asks the policy's actor half, then the gate registered for the tool's name, then `invoke`, for real actions and hand-built tools alike, whether projected or handed straight to `runLlmToolCall`. Arguments the published schema refuses are `X_INPUT_INVALID` and open no row.
- **BREAKING — (#18) A tool gate registered only in a module a worker does not load is `X_ROLE_LOAD_INCOMPLETE` at the `manifest` step.**
- **BREAKING — (#19) `asProjectableAction(handBuilt)` returns a copy behind the gate** rather than the object it was handed; projecting that copy, or a spread of it, passes the gate once.
- **BREAKING — (#20) A failed agent tool shows the model the error's `callerFix`** when it declares one, instead of the developer's `fix`.
- **BREAKING — (#21) `step.run` answers the stored JSON form on every attempt,** and its type says so (`StepOutput<T>`, exported from `@ultimat3/jobs`). A step's object keys read in `jsonb`'s order on every attempt. A `Date` off a step result typechecked and threw only on the resume; it is now a compile error at the read, and if forced, fails on attempt 1.
- **BREAKING — (#22) `step.waitForEvent` requires `schema`,** parses the stored payload on a hit and a replay, and `<T>` is gone.
- **BREAKING — (#23) `isr` and `static` render as nobody.** `load`, `meta` and the page run with the anonymous actor, services rebuilt for it, the default zone, `ctx.url` at the document's address, no inbound headers, and `ctx.ip` and `ctx.peer` `null` (`withAnonymousRequest`, new in `@ultimat3/http`). An ungated `load` reading the actor stored a signed-in visitor's row, and the next anonymous request received it with `public` cache headers. `setRedirect()` in `load` still answers its `Location`.

- **BREAKING — (#25) `@ultimat3/notify`: `x_notify_deliveries` gains `claim_id uuid`.** `DeliveryLedger.claim` answers `owned` (with a `claimId`), `sent` or `held` instead of a boolean, and `settle` takes that `claimId` as a required fourth argument and answers whether it recorded.
- **BREAKING — (#26) A tool in `mcpConfirmations({ tools })` waits on every MCP server in the process,** whether or not that server was handed `confirmations`. `defineAppMcp` asks the gate registered for a tool's name at call time, on every tool a server's own `confirmations` does not gate. The same call answered `X_MCP_CONFIRMATION_PENDING` in-app and ran over MCP.
- **BREAKING — (#27) A gated name no tool answers to reds the `manifest` step with `X_MCP_CONFIRMATION_TOOL_UNKNOWN`.** `mcpConfirmations({ tools: ['refundOrdr'] })` held nothing and the real `refundOrder` ran. A name counts when an exposed action, exposed query, MCP tool or in-process tool answers to it.
- **BREAKING — (#28) `@ultimat3/http`: `'null'` in `cors.origins` is `X_CORS_CONFIG_INVALID` at boot** and is never answered. A sandboxed iframe on any site got `access-control-allow-origin: null` with `allow-credentials: true`.
