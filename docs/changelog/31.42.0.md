## 31.42.0 - 2026-11-17

### Highlights

- **The gate's `live` step holds a strict floor to its word:** a `live` test that skipped with the database in reach is red, and a runner with no database stays a warning. The signal travels through `--json` to `x verify merge`.
- **An island size ceiling can no longer read the coverage build by accident:** a test builder that hands both builds one bundle is refused, `X_TEST_ISLAND_BUILD_REUSED`.

### Fixed

- testing: under the gate's coverage run, `mountIsland` refuses a builder that hands the shipped build the same bundle it handed the coverage build (`X_TEST_ISLAND_BUILD_REUSED`) — a memo round `buildIslands` that ignores `options`. Measured instead, every island size ceiling read the unminified chunk: green under `bun test`, red in `x verify` (one adopter, 14 files). The fix names the call: `mountIsland({ build: buildIslands, root, file })`, or a memo keyed by `options.coverage`.
- `x verify --json` now writes a `live` step's `services` (`reached` / `unavailable`). The step recorded it, but the JSON renderer copies fields by name and dropped it, so a gate part never carried it and `x verify merge` could not apply the strict `live` skip rule to a sharded run.

### Changed

- `live` under a strict floor holds its skips at 0 in CI when `x.verify.json` writes no `skipCeiling.live` **and the run reached its database** (`X_VERIFY_SKIPS_OVER_CEILING`): a test that skipped with Postgres in reach proved nothing. A runner with no database (a macOS or Windows job, a stack docker could not start) keeps today's warning, `X_TEST_SERVICES_UNAVAILABLE`. The step now records `services: "reached" | "unavailable"` in `--json` and in a gate part, so `x verify merge` judges a sharded `live` by what every shard reached. See wiki/Upgrading.md.
