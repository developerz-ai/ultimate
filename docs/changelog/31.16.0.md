## 31.16.0 - 2026-11-13

### Highlights

- `x exercise` is fairer and stricter: a refused test-seed table is one finding instead of every check going unproven, one call is held to 100 statements (loops declared with `expectedQueryLoop` excluded), and a data-dependent branch no longer reads as an N+1. `x.verify.json` `exercise.unprovenMax` / `statementsMax` floors are red when declared, warnings otherwise.
- `x upgrade` installs missing shipped guards the tree already meets and moves the coverage floor on a Bun-floor hop, instead of only printing what to do.
- `x doctor` warns (never fails, on main) on raw SQL against tenant tables with row security off, ranged `@ultimat3/*` pins, applicable verify steps outside the floor, and app env names that collide with a framework switch; `FRAMEWORK_ENV` lists every env name the framework reads.

### Added

- `@ultimat3/core`: `FRAMEWORK_ENV` and `frameworkEnvEntry(name)` — every environment name the framework reads, its owning package and what reading it means (`contract`, `switch`, `internal`, `host`). `bun run framework-env` (`scripts/framework-env.ts`, run by the `unit` step through its test) keeps the list complete: a literal env read in `packages/*/src` the list does not name is `X_FRAMEWORK_ENV_UNREGISTERED`, a listed name no shipped file spells is `X_FRAMEWORK_ENV_STALE`.
- `@ultimat3/testing`: an absolute statement ceiling per primitive call. One call of an action, query or job may send 100 statements (`STATEMENTS_MAX`); above it the record carries `statementCeiling: { verdict: 'over', statements, max, top }` and `statementCeilingFindings()` reports `X_STATEMENTS_OVER_BUDGET` naming the three shapes it sent most. Raise or lower it for one primitive with `defineExercise({ <name>: { statements: { max, why } } })`; a blank `why` is `X_CONTRACT_EXERCISE_UNDECLARED`. Only statements no `expectedQueryLoop` declared are counted, as in the scale sweep (`statementCeiling.expected` holds the excluded count), so a `backfill()` pass is judged on its page reads, never the seed's size.
- `x doctor`: four new checks, reported as warnings — `data.warnings[]` in `--json` (`{ code, cause, fix, docs, at }`), one line each in the terminal — that leave its exit status, `findings` and `data.codes` unchanged; they become findings, red, on `next`. Raw SQL naming a tenant table while `database.rowSecurity` is off — a `sql`, `Bun.sql` or `tx.sql` template, `raw('…')` or `identifier('…')`, comma joins and `delete … using` included (`X_DB_ROW_SECURITY_OFF`, each site listed); gate steps that apply to the app but are not in the `x.verify.json` floor (`X_VERIFY_STEP_UNFLOORED`, run first with `x verify --only`); `@ultimat3/*` dependencies pinned as anything but an exact version or a `workspace:`/`file:`/`link:` path — `^`, `~`, `*`, `x`, a dist-tag, a comparator or hyphen range, an `npm:` alias judged on its own spec (`X_FRAMEWORK_PIN_RANGE`, naming the exact version installed); an app's `envSchema` or sealed secret on a name the framework reads as a switch or for itself (`X_ENV_NAME_RESERVED`, fixed by renaming to `APP_<name>`) — an adapter's own settings and credentials (`S3_*`, `AWS_*`, `SMTP_URL`, `SES_*`, `RESEND_*`, `CLOUDFLARE_*`, `FASTLY_*`) are the contract an app declares, never reported.
- `x.verify.json`: an `exercise` key, `{ "unprovenMax": <ratio 0–1>, "statementsMax": <whole number ≥ 1> }`. `x verify`'s `exercise` step and `x exercise` judge the pass against it: above a declared figure is red (`X_EXERCISE_UNPROVEN_ABOVE_FLOOR`, `X_STATEMENTS_OVER_BUDGET`); without the key each is a warning line naming the figure to write. `x new` writes `{ "unprovenMax": 0, "statementsMax": 100 }`. The ratio is compared in integers (7 of 100 holds `0.07`); `x exercise <name>` is a slice and is not judged against the key; an entry's own `statements: { max, why }` stands against `statementsMax`, at the default figure too.

### Changed

- `x exercise`: a sized-seed table the database refuses is one `X_EXERCISE_SEED_FAILED` naming the entity, the driver's words and the primitives that read it; only those readers are `unproven`, and every other primitive is still scale-judged. Before, one refused table left every primitive `unproven` with the same reason.
- `x upgrade`: a hop installs each missing shipped guard from the target release's own template (`x g guard <name>`) when the `boundaries` step finds nothing more with it on disk; a guard the tree already breaks is withheld and listed with its finding count — every file its `x g guard` run wrote taken back out and the refreshed `x.manifest.json` / `openapi.json` restored to their prior bytes — and an app-edited guard is never touched. `--json` reports `data.guards.installed` and `data.guards.withheld`.
- `x upgrade`: a hop that moves the Bun floor re-measures unit coverage, and when the measurement lands under the `x.verify.json` coverage floor moves the floor to it with a dated `why` — in the hop's diff and in `data.coverage`, never silently.
- `x upgrade`: a hop writes the `exercise` figures its own `x exercise` measured (`unprovenMax`, and `statementsMax` never under 100) into an `x.verify.json` that states none, so the floor starts where the app is (`data.exerciseFloor`) — only from a report that run rewrote, never a stale one. A key the app already wrote is never touched.

### Fixed

- `x exercise`: a primitive that branches on the row it was handed is no longer `X_QUERY_SCALES_WITH_ROWS`. The scale sweep's 8-row graph now opens on the 2-row graph's values — every column but a unique one is drawn from the row's place in its own graph (`seedGraph` with `beside`), so the handed row is the same at both sizes whatever the seed — and a shape sent exactly once at 8 rows and never at 2, with nothing else grown, is `unproven` (another path, not a loop) instead of red. A shape that grew from one or more is still red, and so is one sent more than once at 8 rows and never at 2: a loop over rows the 2-row graph held none of (a filter on a third enum value).
- `x test` / `x verify` no longer strip `CHROME_PATH`, `PUPPETEER_EXECUTABLE_PATH` or `TMPDIR` from a test child when `.env.development` sets them to the value the shell holds: they locate things on the host, and scrubbing them stopped e2e from finding Chrome.
