## 31.52.0 - 2026-11-28

### Highlights

- **Signed live cursors and a versioned device wire:** a resumed live query trusts only a cursor the node signed, and device agents speak `DEVICE_WIRE_VERSION` 1, with published fixtures for non-JS clients.
- **An app-wide egress proxy:** `outbound: { proxy, direct }` in `app.config.ts` routes every `outbound()` call, the AI providers and signed S3 through one proxy.
- **Tenant-safe job status:** `jobStatusFor` and `cancelJobFor` read and cancel one job inside a tenant's fence, on every driver.
- **Query plans as test assertions:** `expectPlanWithin`, `raceActions` and `expectPartial` in `@ultimat3/testing`.
- **Safer writes on custom stores:** a `defineDriver` store with `updateChecked` gets race-free judged updates, `updateMany` rollback and `updateWhereReturning`.

### Added

- `updateWhereReturning(filter, patch)` on a table handle (`@ultimat3/entity`): `updateWhere` that resolves the rows it wrote, so "update if it is still open" returns what this call moved (`[]` when nothing matched). On Postgres one `update … returning *` decides it, with no explicit lock; a filter that does not name the whole primary key is counted first, and a count past `MAX_ASSERTED_ROWS` is refused before the write. A transaction rolls back if concurrent changes push the result past that bound. A `defineDriver` store refuses before writing because it reports counts only. Same plan and guards as `updateWhere` on supported drivers. `Repo.updateWhereReturning` is optional, so a hand-written repository still compiles; the call on one without it is refused with nothing written.
- `outbound({ refusal: { headers: string[] } })`: names response headers (case-insensitive, at most 16) whose values a refusal keeps at `meta.headers`, lowercased, redacted and cut at 200 characters, so a caller can quote a vendor's request id. A credential-named header or a malformed list is `X_INVARIANT` before a byte is sent; unset, nothing changes. See [Outbound HTTP](https://github.com/developerz-ai/ultimate/wiki/Outbound-HTTP#refusal-what-a-non-2xx-body-becomes).
- `@ultimat3/ui`: four alias colour roles, `link`, `link-strong`, `nav-active` and `focus`, each **defaulting to the accent** (`COLOR_ALIASES`, `ALIAS_ROLES`, `THEME_ROLES`, `ThemeRole`). `Link`, plain `<a>`, a hovered `Breadcrumb`, the current item of `NavList`, `BottomNav` and `Tabs`, `t.focus-ring` and every control's focus outline read them; unset, `t.role(link)` compiles to `rgb(var(--color-link, var(--color-accent)))`, so an app renders exactly as before. `defineTheme({ colors: { light: { link, focus } } })` splits one off, measured against the new `ALIAS_CONTRAST_PAIRS` (4.5:1 text, 3:1 the ring), and an accent-only brand is measured as the link and ring it becomes. `colorVar`, `color` and `colorRgb` take an alias role. See [Theming](https://github.com/developerz-ai/ultimate/wiki/Theming#alias-roles-links-navigation-focus).
- `@ultimat3/i18n`: the framework's own strings — `ui.*`, `errors.*`, `auth.*`, `admin.*`, `pagination.*`, `validation.*`, `common.*`, `time.*`, `dev.*` — ship in Romanian, Spanish and Brazilian Portuguese beside English (`FRAMEWORK_CATALOGS`). An app catalog stands on the one in its language, matched on the canonical tag (`pt-br` on `pt-BR`, `es-MX` on `es`), its own strings on top; nothing to wire. A shipped language the app does not register never enters its `registeredLocales()`, and a language the framework does not ship still misses loudly. See [I18n](https://github.com/developerz-ai/ultimate/wiki/I18n#catalogs).
- Split i18n catalogs: an app's locale may be a directory, `packages/i18n/catalogs/<locale>/<namespace>.json`, one file per namespace holding that namespace's subtree (a folder is a deeper one: `site/home.json` holds `site.home.*`), joined by a generated `catalogs/<locale>/index.ts` that `packages/i18n/src/index.ts` imports as `import { catalog as en } from '../catalogs/en'`, so `typeof en` is still the typed key space. `bunx x i18n split [<locale>]` migrates a flat catalog losslessly and idempotently, rewriting the index import and widening `.gitattributes`' catalog rule to `catalogs/**/*.json`. `x i18n check`, `sync` and `add`, every `x g` generator, the merge driver, the `untranslated-string` guard and every finding read and write both forms; a locale with both is `X_CATALOG_LAYOUT_MIXED`, one key in two files `X_CATALOG_KEY_DUPLICATE`. The flat `<locale>.json` is unchanged and stays what `x new` writes. See [I18n](https://github.com/developerz-ai/ultimate/wiki/I18n#split-catalogs).
- `@ultimat3/testing`: `expectPlanWithin(sql, { maxCost, maxSortRows })` reads `explain (format json)` and refuses a plan over budget with `X_QUERY_PLAN_OVER_BUDGET`, naming the index to add; `raceActions(calls, { rounds })` runs actions concurrently and reports `40P01`/`40001`; `expectPartial` asserts a `decide()` answer. See [Testing](https://github.com/developerz-ai/ultimate/wiki/Testing).
- `@ultimat3/policy`: `evaluateEach(policy, { input, actor, rows })` — one decision and one event per row. `@ultimat3/action`: the handler's `decide(rows)` (`ActionDecideArgs`, declared through `DecidingActionDef`) answers `{ allowed, denied: [{ row, code, reason }] }` on the action's own policy and surface; a missing (`null`) row is denied.
- `@ultimat3/jobs`: `jobStatusFor` / `cancelJobFor` — a tenant's fenced read and cancel of one job (a foreign job reads as missing), over `JobDriver.tenantJobs` on the memory, Postgres and Redis drivers. The reference app's `postsExportStatus` and `cancelPostsExport` use them.
- `@ultimat3/auth`: `issueVerification({ to })` mails a recipient distinct from the store key, only on a purpose declared `defineVerificationPurpose({ recipient: 'explicit' })` (the member invite); a `to` on any other purpose, or a blank one, is `X_CONFIG_INVALID` before any write, so a reset or sign-in link always goes to the inbox it is keyed by.
- `@ultimat3/realtime`: `DEVICE_WIRE_VERSION = 1`. A device hello carries `v` (absent reads as 1); the agent closes a newer node with `X_DEVICE_WIRE_VERSION`. The frames are published for non-JS clients as `@ultimat3/realtime/wire/device-v1.json` and `./device-wire-frames`, held to the code by `scripts/device-wire.ts --check`.
- `@ultimat3/realtime`: live cursors are signed (`sig` on `LiveCursor` and `PatchFrame`); a mismatched signature cold-starts, an unsigned cursor still resumes and is counted (`registry.unsignedCursors`, `onUnsignedCursor`). Refusing unsigned cursors waits on `next` (#1280).
- `app.config` `outbound: { proxy, direct }`: an app-wide egress proxy for every `outbound()` call and the AI providers; a per-call `proxy` wins, `proxy: () => undefined` dials direct, loopback and `direct` hosts are never proxied. `Bun.S3Client` cannot be proxied (documented). See [Configuration](https://github.com/developerz-ai/ultimate/wiki/Configuration).
- `@ultimat3/entity`: a `defineDriver` store may implement optional `updateChecked` (compare-and-set); judged updates then re-judge a raced row and refuse `X_DB_SERIALIZATION_FAILURE` after 16 retries, and `updateMany`'s rollback keeps a row another writer changed; `updateWhereReturning` is available on such a store. A store without it warns once (`entity.driver.update_unchecked`).
- `@ultimat3/action`: an input key the schema does not declare is reported (`X_INPUT_UNKNOWN_KEY`), so a typo stops being silently dropped. Refusing it outright waits on `next` (#1281).

- `x.verify.json` `localOnly: { "<step>": "<why>" }`: under `CI` the named steps leave the gate; on a developer's machine they run as before, and `--only <step>` runs one anywhere — for a check the author's own run answers, such as a real-browser pass. A CI run names each step it left out, with its why, in a line under the step table and in `data.localOnly`. An unknown step or an empty why is a `manifest`-step problem. Unset, nothing changes. See [CLI Reference](https://github.com/developerz-ai/ultimate/wiki/CLI-Reference-Gate#x-verify).

### Changed

- Telemetry resource: a served role's `service.name` is `OTEL_SERVICE_NAME`, then `OTEL_RESOURCE_ATTRIBUTES`' `service.name`, then the app name; `service.version` is the attributes', then `BUILD_ID`, then `APP_VERSION`. A process that never booted an app (a script, a test, a bare `x` command) reports `unknown_service`, the OpenTelemetry default, where it reported `ultimate`/`0.0.1`. `installTelemetry` on `@ultimat3/core/adapter` installs the same resource and returns its release. A dashboard filtering `service.name="ultimate"` now reads `unknown_service` — see [Upgrading](https://github.com/developerz-ai/ultimate/wiki/Upgrading).
- `keyedFingerprint` caches the derived purpose key (at most 64, cleared on secret rotation, compared with `timingSafeEqual`): about 4 µs a call, from 14–20 µs.
- `x db migrate` and `x db rollback` beside a live `x dev` work with `database.rowSecurity` on the embedded database: they run as `x_migrator` under an exclusive hold of the session, and a failed restore of `x_app` stops serving with `X_DB_ROW_SECURITY_BYPASSED`. The `X_NOT_IMPLEMENTED` refusal is gone.
- Security advisories: `scripts/lib/advisory-acknowledged.ts` acknowledges an advisory no floor can fix, with an expiry; `sass` → `immutable`/`source-map-js` is acknowledged until 2027-02-25 (apps: `bun update immutable source-map-js`). An expired or stale acknowledgement is `X_ADVISORY_ACK_EXPIRED` / `X_ADVISORY_ACK_STALE`.
- `wiki/CLI-Reference.md` is an index over six pages: Project, Data, Gate, Ship and Tools.
- `x new --shape offline`: the `/posts` JS budget is 157kb, up from 156kb. It measured 159,827 B; the page boot now keeps the live cursor's `sig` (+253 B).

### Fixed

- `subjectExport()` / `subjectErase()` work when the subject IS the tenant (`defineSubject(orgs, …)` in a multi-tenant app): each direct child was read with `in [<org id>]` on its tenant column, which the tenant guard refuses unless it is `eq` the actor's org, so every child was `X_TENANCY_ACTOR_MISMATCH`. A single parent key is now read with `eq`; several keys keep `in` (they never reach a tenant column). See [Jobs and workflows](https://github.com/developerz-ai/ultimate/wiki/Jobs-And-Workflows).
- `x verify`'s `contract-diff` step classifies an input schema that only ADDS values to an `enum` (a new webhook topic, a status a filter takes) as `additive`, not `breaking`, when the enum sits where accepting more cannot refuse anything (`properties`, `items`, `anyOf`, `allOf` and their like): every payload the old schema accepted, the new one accepts. A widening under `oneOf`, `not`, `if` or `const`, a removed value, or any other change beside it is still `breaking`; an enum only reordered is no change.
- `x shot --island` judges a picture by its pixels, not its byte count: a crop every pixel of which is one colour (within 2 levels per channel) or fully transparent is `X_SHOT_ISLAND_UNPHOTOGRAPHABLE` with the crop's fix, and bytes no decoder reads keep the browser's. The 512-byte floor refused a real 36 px flat button (372 bytes) as blank; `MIN_SHOT_BYTES` is now the smallest complete PNG, 67, a backstop only.
- `Dialog` and `Drawer` reserve the close button's column: the header is a `minmax(0, 1fr) auto` grid and the title wraps with `overflow-wrap: anywhere`, so a long title ("Redenumește acest PC", one unbreakable word) no longer runs under the × or squeezes it at 320 px, in either direction (`packages/cli/e2e/ui-dialog-header.e2e.test.ts`).
- `@ultimat3/ui` scroll containers no longer set `overscroll-behavior: contain`, which trapped page scroll on Chrome 144+ inside the `AppShell` sidebar and `Table`; modal surfaces (dialog, `Drawer`, `CommandPalette`, `SearchableSelect`) contain explicitly (#1289).
- `defineDriver` `updateWhere` raced a concurrent writer: a judged update could write a row that no longer passed its predicate (#1379).
- Test discovery skips `.claude/worktrees/`, so a worktree's tests never run under the root config (#1287); four `packages/cli` tests that failed on some seeds are order-independent (#1372, #1285, #1239).
