## 31.0.0 - 2026-11-10

### Highlights

- **v31 is the stable line.** 74 breaking changes — most delete a second way to do one thing, the rest are security fixes and limits — each with its edit in [Upgrading](https://github.com/developerz-ai/ultimate/wiki/Upgrading#30x--3100-entry-by-entry). The next major comes no earlier than 2027-02-08, 90 days from today ([Stability](https://github.com/developerz-ai/ultimate/wiki/Stability)).
- Every backend is a port: 31 adapter ports, each set in `runtime.ts`, each exported from a package's `./adapter` and each with a conformance suite in `@ultimat3/testing/conformance` to check your own implementation against.
- One instrumentation bus carries every span, metric and log, and the spans use OpenTelemetry's stable http, db, messaging and gen_ai attribute names. Exporters subscribe to the bus.
- Scale and big data: partitioned tables, a double-entry ledger, fleet-wide locks (`withLock`), a search index, upload scanning, `pdf()`, a job worker about 25× faster on a backlog (31 → 799 claims/s for one worker), a faster boot and `x verify --changed`.
- Security and trust: SAML single sign-on built in, fixes from the security review (cache entries keyed by the caller's grants as well as their id), an OpenSSF Scorecard and private vulnerability reporting.

### Changed

- `@ultimat3/jobs`: a worker drains a backlog at the speed of its jobs, not one batch per poll interval. A pass that found work used to wait the whole floor (250 ms) and a freed slot could not cut it short, so the defaults capped one worker at 8 jobs × 4 passes = 31 claims/s; a pass whose every claimed row started now marks a backlog and the next freed slot claims at once — 799 / 1,618 / 2,277 claims/s at 1 / 4 / 16 workers on the same bench (`scripts/bench/results/worker-throughput.json`). The poll interval is the idle backoff only.
- Scale ladder, measured (plan 101 slice 22): `scripts/bench/{worker-throughput,fanout-3-nodes,boot-vs-files,http-prod-image}.bench.ts` with committed results, held to their prose by `bun run scripts/bench-claims.ts` (`X_BENCH_CLAIM_STALE`); `docs/idea/17-scale-ladder.md` cites one measurement per rung and drops two stale rows (read replicas are wired per request; `redisJobDriver` ships). `@ultimat3/jobs`: `scheduler-failover.live.test.ts` kills the scheduler leader mid-fire — no double fire, no skip.
- `@ultimat3/render`, `@ultimat3/cli`: an app workspace may be named `api`, `site`, `app` or `shared` — the surface is the directory directly under `apps/<name>/` (`locateSurface`), where it took the first such segment and `apps/api/site/x/page.tsx` was `X_ROUTE_FILE_INVALID`. The `boundaries` step resolves `@<app>/<workspace>/…` onto `apps/<workspace>/…`, so a `site/` page importing a sibling app's `app/` is `X_BOUNDARY_SITE_TO_APP`. An `app/` module importing a SIBLING app's `api/` registry by value (`apps/admin` projecting `apps/web`'s actions) is allowed: `app/ → api/` stays types-only inside one app, where it is a registration cycle. New `manifest` finding `X_PARTITIONS_UNMAINTAINED`: an entity declaring `partitionBy` with no `partitions()` job registered.
- `@ultimat3/auth`: SAML 2.0 SSO, no dependency, beside OIDC behind one `IdentityProvider` port (`begin` / `complete` → one `OAuthProfile`; `signInWithIdentity` is the one way to a session). `samlIdentityProvider({ id, idp: parseSamlMetadata(xml), spEntityId, trustEmail })`: SP-initiated (AuthnRequest over HTTP-Redirect, RelayState), ACS over HTTP-POST, XML-DSig verified in-package (strict XML reader refusing DOCTYPE/entities/PIs, exclusive c14n proven against xmlsec-signed vectors, RSA-SHA256 ≥ 2048, keys from metadata only), the assertion itself signed and the only one in the document, Recipient/Destination/InResponseTo/Audience/NotBefore/NotOnOrAfter checked, each assertion claimed once in `auth.totpReplay`. `oidcIdentityProvider({ provider })` puts the existing OAuth/OIDC handshake behind the same port. `identityProviderRoutes(auth, { providers })` serves `GET /auth/sso/:provider`, `GET|POST /auth/sso/:provider/callback`. New codes `X_SAML_RESPONSE_INVALID` (400, `meta.check`), `X_SAML_METADATA_INVALID`, `X_IDENTITY_PROVIDER_UNKNOWN` (404). `identityProviderConformance` in `@ultimat3/testing` holds an adapter of your own to the contract.
- `@ultimat3/cli`: `x g app <name>` / `x g package <name>` add a workspace (`apps/<name>/`, `packages/<name>/`) named `@<scope>/<name>` off the root manifest, and print `bun install` then `bunx x verify --changed --dirty`; a name the other kind holds is `X_WORKSPACE_NAME_TAKEN`. `--app <name>` (default `web`) lands `x g route|island|query` in another app workspace; a generator that registers in `apps/web` refuses it (`X_CLI_BAD_FLAG`)
- `@ultimat3/cli`: the app scan imports its modules in batches of 256 — one generated entry module per batch, statically importing it in scan order, so every module evaluates in the order the serial loop evaluated it (`app-load-order.test.ts` snapshots both), then registers in that order; a batch with a module that fails falls back to one import at a time for its own finding. `x build --target prebuilt` can write a module registry (`node_modules/.cache/ultimate/registry/`) that `web`, `sync` and `replicator` import at boot instead of scanning; a registry whose module list is not the disk's is logged as `X_PREBUILT_REGISTRY_STALE` and the boot scans. `x g` loads the app to refresh `x.manifest.json` only when a written file is an app module, declares an `X_*` code or sits at the app root — `x g island` no longer loads the app. 5,000-module fixture (2026-11-09, loaded host): untracked scan 2.2 s → 1.6 s, prebuilt boot 1.1 s, tool load (`loadApp`) 4.8 s → 2.2–3.1 s; `x g island` on the reference app 1.16 s → 0.59 s
- `@ultimat3/scraping`: `pdf({ input, policy, route, key, storage, layout?, headers?, origin? })` — a factory over `action` (a `PRIMITIVE_FACTORIES` row) that renders one of the app's own routes to PDF through Chrome over raw CDP (`Page.printToPDF`), writes it to a disk and answers `{ key, bytes, contentType }`; schema, policy, rate limit, meter and audit are the action's. A route leaving the origin is `X_SCRAPE_PDF_ROUTE_INVALID`, no `APP_URL`/`origin` `X_SCRAPE_PDF_ORIGIN_MISSING`, a 4xx/5xx page `X_SCRAPE_PDF_ROUTE_FAILED`. The raw-CDP launcher and connection moved from `@ultimat3/testing` to a new entry point, `@ultimat3/scraping/cdp`, which now registers the four `X_CDP_*` codes; `@ultimat3/testing` re-exports every name unchanged.
- `@ultimat3/notify`: a new adapter port, `smsTransport` (`SmsTransport` on `@ultimat3/notify/adapter`, `smsTransport:` in `runtime.ts`, `smsTransportConformance` in `@ultimat3/testing/conformance`), and the reference `smsChannel({ message })`: one SMS per recipient, the body a catalog key rendered in the recipient's locale, one idempotency key per delivery. `memorySmsTransport()` is the default in development/test; elsewhere a send with none installed is `X_NOTIFY_SMS_TRANSPORT_MISSING`, and a non-E.164 number `X_NOTIFY_SMS_NUMBER_INVALID` (both terminal). Providers (Twilio, Vonage, SNS) are the app's adapters.
- `@ultimat3/cli`: `x verify --changed [--base <ref>] [--dirty]` runs only the steps whose inputs the diff touches — each changed file gets one rule (`doc`, `test`, `source`, `drift-input`, `generated`, `root-config`, …), each rule selects steps, `data.changed` names the files behind every step; NOT A GATE RUN, refused beside `--only`, fail-open on any path no rule speaks for. `drift` runs only when an entity, a module an entity imports, `packages/db/**`, a generated client or `openapi.json` moved. On a 3-app + 2-package scaffold (full gate 52 s): a docs-only diff 8.9 s, a test-only diff 9.3 s, a `packages/ui` edit 39.8 s. `x new`'s root tsconfig reaches every workspace through one alias (`@<app>/*` → `packages/*/src`, then `apps/*`), so a new `apps/<name>` typechecks with no tsconfig edit. New code `X_APP_ROOT_NESTED`: an `app.config.ts` inside a workspace is a second app root — one repository is one app, one image, one migration owner.
- `@ultimat3/jobs`: four mechanisms over existing primitives. `ledger({ name, tenant, book })` — a job posting double-entry Money, every currency summing to zero on its own, refused before any write (`X_LEDGER_UNBALANCED`, `X_LEDGER_ENTRY_INVALID`, terminal), written in one step and idempotent by `(tenant, postingKey, line)` through `entityLedgerBook` over the app's own entity; a key re-used with other entries is `X_LEDGER_POSTING_CONFLICT`, nothing written. `withLock(key, fn, { ttl, wait? })` — one holder fleet-wide over the driver's `LeaseStore`, a fencing `token` (the lease store's number, `x_job_leases.fence` from one sequence — never a client clock) and an abort `signal` handed to `fn`, a hung renewal a loss once the ttl lapses (`X_LOCK_NOT_ACQUIRED`, `X_LOCK_LOST`, `X_LOCK_STORE_MISSING`). `reindex({ name, entity, source, tenant })` — a `backfill()` rebuilding the `searchIndex` port. `personalDataProblems()` — proof the `defineSubject()` declarations erase every `personalData()` column (`X_PERSONAL_DATA_UNERASED`, `X_PERSONAL_DATA_UNREACHED`); `subjectExport`/`subjectErase` stay the one export/erase path. A subject run refuses an incomplete declaration before touching a row, `x exercise` lists both codes, and `subjectErase` writes its erase to the installed `auditSink` (`allowed` once per completed erase, `failed` per attempt that threw; `input: { subject, run }`). `partitions()` — a job plus its `.schedule` task (03:17 UTC daily) running `@ultimat3/db`'s `partitionMaintenance` for every `entity({ partitionBy })` at the job's clock: partitions created `ahead`, expired ones dropped.
- `@ultimat3/cache`, `@ultimat3/cli`: cache and ISR invalidations reach every replica on rung 1 (Redis, no NATS). With the in-process bus and `REDIS_URL` (else `VALKEY_URL`) set, the hop rides Redis pub/sub (`redisPubSub`, `redisPubSubAt`); NATS or a supplied `transport` stays the path when configured. One rule, one boot line: `cache.broadcast bus=<redis|nats|in-process> source=<key>`. A dropped subscriber connection is resubscribed and the process's own tiers flushed, because pub/sub keeps nothing for the window it was away. Before, a write on one web replica left the others serving stale pages and `cache:` reads until TTL.
- `@ultimat3/entity`: `personalData(kind, column)` marks a column as personal data (`identifier` / `contact` / `free-text`) without moving its DDL; `personalDataOf(entity)` and `personalDataEntities()` list every marked column per registered entity, for a GDPR export or erase job. A new adapter port, `searchIndex` (`SearchIndex`: `index` / `remove` / `query`, tenant-scoped): `postgresSearchIndex()` — `.searchable()`'s generated `tsvector`, the default — and `memorySearchIndex()`, the reference; Meilisearch or Typesense is the app's, proved by `searchIndexConformance` (`@ultimat3/testing/conformance`) and returned as `searchIndex` from `runtime.ts`.
- `@ultimat3/storage`: a new adapter port, `uploadScanner` (`UploadScanner`: `scan({ key, size, contentType, body })` → clean / infected), returned from `runtime.ts` and asked by `promoteAttachment` about a per-attempt copy (`pending/scan/`), which is what gets attached when clean — a refused confirm never touches the row's key. Infected: the upload and its copy deleted, `X_STORAGE_UPLOAD_INFECTED` (422). No verdict: fails closed in every environment, `X_STORAGE_SCAN_UNAVAILABLE` (503), the upload left pending for a retry — `uploadPolicy({ onScanUnavailable: 'accept' })` promotes unscanned instead. `memoryUploadScanner()` flags the EICAR test string (`EICAR_TEST_STRING`); `uploadScannerConformance` (`@ultimat3/testing/conformance`) proves an app's ClamAV adapter. No scanner installed, nothing changes. And `variant(key, { disk, images, width, format? })`: one resized image made by the `images` driver passed in (any `ImageTransformDriver`) and kept under `variantKey(…, { revision })` — a second call is a `stat`; a non-raster source is `X_IMAGE_UNSUPPORTED`.
- `@ultimat3/testing`: conformance suites for the realtime, AI, scraping, secret and clock ports — `transportConformance` (in-process, NATS on the in-memory server and a real nats-server), `gatewayConformance` (budget scope and ledger included), `providerConformance` plus `providerTransportConformance` for an HTTP provider (abort reaches `fetch`, an echoed key never reaches an error, an endless error body ends, a context overflow is `X_AI_CONTEXT_OVERFLOW`), `vectorStoreConformance` (memory, pgvector), `scrapeDriverConformance` (fake, fixture), `secretSourceConformance` (env, file, default, an app's KMS source) and `sleepClockConformance` (system, frozen, no-wait — the abort reason verbatim, no listener left behind). `@ultimat3/realtime`'s `transport-parity.test.ts` is deleted in their favour, and the socket cases leave `@ultimat3/ai`'s `provider-parity*.test.ts`.
- `@ultimat3/testing`: a new entry point, `@ultimat3/testing/conformance`, holds every port's suite (`behavesLike(<port>Conformance, () => yours)`; the README's table lists them). `entityDriverConformance` holds an entity `Driver` to what `db.<table>` promises — writes, keys, values, reads, upserts, soft delete, append-only, seeds, aggregates, tenancy, preload, locks, every column kind — over memory, Postgres on PGlite and a real server, and a `defineDriver` store; a capability the subject does not declare is asserted refused. Ten of `@ultimat3/entity`'s `*-parity.test.ts` are deleted in its favour; seven keep only what no driver promises.
- `@ultimat3/testing`: five conformance suites for credential and limit stores — `rateLimitStoreConformance` (memory, Postgres, Redis), `authLimiterFactoryConformance` and `totpReplayGuardConformance` (memory, Postgres), `authServerStoreConformance` (memory, Postgres) and `authAdapterConformance` (every `AuthAdapter` sub-store; memory, Postgres on PGlite and a real server). `behavesLike(suite, () => yours)` proves a hand-written adapter; `@ultimat3/auth`'s `adapter-parity*.test.ts` and `authorization-server-store.contract.test.ts` are deleted in their favour.
- `@ultimat3/mcp`: `X_MCP_CONFIRMATION_QUORUM_PENDING`'s `meta` names the outstanding approvers (`meta.outstanding`: the stored `actor:<id>` / `role:<name>` selectors still able to vote, never the requester or one who already voted) — additive.
- `@ultimat3/testing`: test doubles, one way each, put back by the preload after the test that made them (outside a test, at its file's end): `stub(action | llm() | query | job)` replaces the body only (a query's rows) — policy, input parse, output schema and every surface stay real — with `.returns(...)`, `.throws(error)` and `.calls`; `swapAdapter(port, impl)` swaps any process-global `ADAPTER_PORTS` port; `toHaveBeenCalledWith` on a stub (schema-checked input; bun's own for a `mock()`), `toHaveEnqueued(job, input?)` on `runJobs`, `toHaveSentMail(mail, { to })` on `mail`. New codes `X_TEST_STUB_UNANSWERED`, `X_TEST_STUB_TARGET_UNSUPPORTED`, `X_TEST_EXPECTED_INPUT_INVALID`, `X_TEST_ADAPTER_PORT_UNSWAPPABLE`, `X_TEST_SCOPE_UNINSTALLED`, `X_TEST_RUN_JOBS_EXPECTED`, `X_TEST_MAIL_EXPECTED`.
- `@ultimat3/admin`: the `/_x` DB panel's `readOnlySql` runs every statement as the SELECT-only role (`ensureReadOnlyRole`, resolved once per runner) inside its read-only transaction — the layer MCP's `db.query` already had; a database that refuses `CREATE ROLE` still answers without it. `/_x/timeline` draws a span whose parent is not in the recording at depth 0 instead of dropping it. `@ultimat3/testing`: `entitySeedWriter`'s row digest is `canonicalJson` (bytes no longer digest equal to their hex text).
- `@ultimat3/render`: the SSR walker is synchronous until the tree holds something to await — a 50k-row table went from ~26× a template string to ~5×, and what the walk holds live from ~198 MiB to 10.6 MiB (the walker flattens its output rope every 1,024 fragments — unflattened it held 100.5 MiB, ~3.2M string cells; the earlier ~42 MiB figure was a GC-timing reading, 6.5–100 MiB on the same code). Measured 2026-11-10 by `scripts/bench/render-html.bench.ts`, one local machine; `render-html.bench.test.ts` holds < 16 MiB live at 50k rows. `memoryIsrStore` is bounded in bytes as well as entries (`maxBytes`, `DEFAULT_ISR_MAX_BYTES` = 256 MiB of `html.length`) and evicts the least recently USED page — a hot page read on every request is no longer evicted before cold ones generated after it; a page larger than the whole cap is not kept. `NAVIGATION_MODAL_ATTRIBUTE` is on `@ultimat3/render/client`.
- `@ultimat3/jobs`: an event published inside a transaction is never missed by a wait that began between its INSERT and its COMMIT — it was stamped before the wait and skipped until the 24 h timeout. A new wait records its snapshot (`EventLookup.mark()`, optional) and `find` also matches every event that snapshot could not see (`x_job_events.xact`, added by the boot's DDL). A waking bus publishing inside `withTransaction` wakes its waiters again at COMMIT, so a run that parked while the transaction was open resumes then, not at the 15 min backstop. `@ultimat3/scraping`'s `eventPrompt` searches under the same mark. The wait cursor is `(published_at, id)` compared, never looked up, on both buses (stamps truncated to the ms), so a purged cursor no longer re-hands an earlier event. The outbox relay runs the next pass at once after a full batch (was capped at 2,500 rows/s); `ratePerTenant` keeps its window as a queue (20k acquires: 8.6 s → milliseconds); the memory bus indexes events by name and sweeps at most once a second; the retention sweep seeks `done` rows through a new partial index `x_jobs_done_idx`.
- `@ultimat3/realtime`: the replication stream notices a half-open walsender. Every timer standby update asks for a reply (`replyRequested = 1`); three status intervals with the pump waiting and nothing read, or a standby update still unsettled at three intervals, end the stream — `stats().failure` set, socket destroyed with no goodbye, `onEnd` called — instead of ~15 min of silence with `/readyz` green. A run let go is fenced off the next one. `openLocalStore` waits out an IndexedDB open `blocked` by another tab (`blockedTimeoutMs`, default 5 s) instead of falling back to memory, and closes its connection on `versionchange`. `RecordStore.settle` splits a wide write in linear time. Every replication and replicator-lock session asks the server for TCP keepalives (`tcp_keepalives_idle=10`, `_interval=5`, `_count=3`), so a holder lost without a FIN frees the advisory lock in ~25 s, not ~2 h. A slot postgres invalidated (`wal_status = lost`) is refused with `X_REPLICATION_SLOT_INVALIDATED` and the `pg_drop_replication_slot` that fixes it; a slot gone under a resume position is recreated, logged `X_REPLICATION_SLOT_RECREATED`, and the replicator says so on the bus (`x.change.-resync`, owed until published) so every sync node re-reads every window and channel at once. `OfflineQueue.open(store, { maxQueued })` caps the outbox: a new key past it is `X_OFFLINE_QUEUE_FULL`, nothing queued is dropped.
- **BREAKING — (#1) `@ultimat3/auth`: an authorization code is spent only by a request that could redeem it.** `exchangeCode` reads the code (`AuthServerStore.getCode`, new and required), checks client, PKCE verifier, `redirect_uri` and `resource`, and only then `takeCode`s it: a request without the verifier — another client, an intercepted code — no longer burns the login, and replaying a spent code without its verifier no longer revokes the grant it minted. `pollDevice(hash, clientId, at)` takes the client and stamps nothing for another client's poll, so it cannot `slow_down` the device. A hand-written store adds both.
- **BREAKING — (#2) `@ultimat3/db`: `identifier()` refuses a NUL and a name over 63 bytes** (`X_SQL_UNSAFE`) — Postgres truncated it silently.
- `@ultimat3/db`: a pooled `select` in flight when `ctx.signal` aborts is cancelled on the server and its connection returned (`X_ABORTED`, or the coded reason) — a hung-up caller no longer holds a pool connection until `statement_timeout`. Writes, pinned statements and statements sent after the abort are untouched. `keyset()` refuses a `direction` other than `'asc'`/`'desc'` and an unknown `kind` (`X_INVARIANT`) and never splices the caller's direction text. `introspectSchema()` sends its eight catalog reads together. `@ultimat3/ai`: `ddlSql()` names a pgvector store's index `<table>_<column>_idx` while that fits in 63 bytes, else a clipped head plus a hash — a long table's three index names had collapsed into one, and the second and third `create index if not exists` skipped silently. `dbDiagnostics({ deadlineMs })` widens the probe and the command budget; `x db diagnostics` passes 30 s on the embedded database, whose cold boot answered `X_DB_UNAVAILABLE`.
- **BREAKING — (#3) `@ultimat3/core`: a drain that abandoned work exits 70, not 0.** `installSignalHandlers({ exit: true })` exits `drainExitCode()` — `DRAIN_TIMEOUT_EXIT_CODE` (70, `EX_SOFTWARE`) when a shutdown hook or in-flight work was still running at the deadline (`X_SHUTDOWN_TIMEOUT`), `0` for a clean drain — so the platform's exit record no longer calls a half-done write a clean stop. Also 70 when the drain threw before its last phase, and from `x start`'s hold when the app's own teardown was abandoned.
- **BREAKING — (#4) `@ultimat3/schema`, `@ultimat3/core`: a refusal is bounded.** Validation stops collecting at `MAX_ISSUES` (100, exported) and marks the result `issuesTruncated: true` — a 10k-item invalid body costs a hundred checks, not 289 ms and a 7.2 MiB problem; `validate`/`validateAsync` take `{ maxIssues }` (`X_SCHEMA_ISSUE_CAP_INVALID` for a cap below 1). Every `UltimateError` and `SchemaError` cause is cut at `MAX_CAUSE_LENGTH` (4096) by `boundedCause`, so `message`, the log line and the problem `detail` carry the same bounded text.
- `@ultimat3/core`: `sentryErrorReporter` takes `beforeSend(event)` (return `null` to drop; a throwing hook drops), `ignore(code)`, `fingerprint(report)` and `sampleRate` (0..1, `X_CONFIG_INVALID` outside it). `sentryEvent()` is the pure event builder. `cursor.ts` verifies through the one `timingSafeEqual`.
- `@ultimat3/auth`: the login limiter's per-address bucket (`ipKey`) counts a network — IPv4 whole, an IPv4-mapped IPv6 as that IPv4, any other IPv6 by its /64 (core's `addressNetwork`) — so rotating through one /64 no longer mints a fresh attempt budget per address. A lockout on one host of a /64 now holds the whole /64.
- `@ultimat3/auth`: `verifyApiKey` writes `lastUsedAt` at most once per `API_KEY_TOUCH_MS` (60 s, exported) instead of on every request, and refuses a key whose `env` segment is not the one it was issued with (`X_API_KEY_INVALID`, the same refusal as any bad key) — a `dev` key relabelled `ult_prod_…` no longer verifies.
- **Release policy: the 90-day major window counts from v31, not v30** (ruling 2026-11-09, [Stability](https://github.com/developerz-ai/ultimate/wiki/Stability)). v31 ships inside 90 days of v30 and is never refused; a v32 inside 90 days of v31 is (`X_RELEASE_MAJOR_WINDOW`). Until v31 ships, a `BREAKING —` entry may reach `main` (`X_BREAKING_ON_MAIN` reads no window) and the deprecation rule is inert. Every release from 30.0.0 still opens with `### Highlights`.
- `@ultimat3/policy`: `guardPrimitive(kind, policy, subject, surface)` — the one policy gate `@ultimat3/action` and `@ultimat3/query` adopt, with its surface table `PRIMITIVE_POLICY_SURFACES` (an MCP read is judged on `mcp`, as an MCP action is) and `denialCode`/`denialReason`, which read an MCP denial's reason without its `<code>: ` prefix. `@ultimat3/mcp`: a projected query tool's `admit` asks its policy on `'mcp'`, the surface its `run` uses, not `'server'`.
- **BREAKING — (#5) `@ultimat3/cache`: `redisTier({ maxValueBytes })` caps an encoded value at 1 MiB by default** (`X_CACHE_TOO_LARGE`, as the LRU's `maxBytes`) — a multi-megabyte value no longer blocks the Redis every replica shares.
- **BREAKING — (#6) `@ultimat3/cache`: Redis tag buckets stay bounded, and a bust is paged.** Buckets are sorted sets (`t2:`/`e2:`) scored by the member's expiry plus a 60 s skew grace; every write prunes the dead, so an entity written constantly and never invalidated no longer collects every key it ever wrote. A bust pages each bucket with `ZSCAN` (~1,000 members a call; a concurrent prune or re-score skips nothing), `UNLINK`s instead of `DEL`, and sweeps 8 `ZREM`s at a time: 10k members in 25 sequential round trips, was ~3,000. `REDIS_INVALIDATE_SCRIPT` and `REDIS_TAG_MEMBER_SCRIPT` are no longer exported.
- **BREAKING — (#7) `@ultimat3/money`: a `fromDecimal` parse failure is `X_MONEY_NOT_DECIMAL` (422), not `X_MONEY_NOT_INTEGER`.** A non-string (`12.99` from a JSON body, `null`, `undefined`) is refused with it too, where `.trim()` threw a bare `TypeError`; the refused input reaches the `cause` bounded and on one line. `parseAmount` refuses a non-string as `X_MONEY_INPUT_INVALID`.
- `@ultimat3/time`: `businessDaysBetween` and `addBusinessDays` count whole weeks arithmetically and ask `Intl` only for offset samples — 30 years ~6 ms (was ~830 ms), 5,000 business days ~4 ms (was ~500 ms), same answers. `formatRelative` and `ordinal` reuse their `Intl` formatter instead of building one per call.
- `@ultimat3/seo`: a sitemap `lastmod` naming a day its month does not have (`2026-02-30`) is dropped, not rolled to March 2nd — `sitemapDatetime` reads `@ultimat3/schema`'s `isIsoDateTime`, as feed dates do.
- **BREAKING — (#8) `@ultimat3/http`: an IPv6 caller is rate limited by its `/64`.** `@ultimat3/core`'s `addressNetwork(ip)` keys every anonymous bucket and the failed-credential allowance: IPv4 whole, an IPv4-mapped IPv6 its IPv4, any other IPv6 `<first four hextets>::/64`. One subscriber holds a /64, so the full address handed it 2^64 fresh buckets.
