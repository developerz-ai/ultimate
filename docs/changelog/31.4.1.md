## 31.4.1 - 2026-11-11

### Highlights

- An island that throws an app error code ships about half the bytes: import `defineError` from `@ultimat3/core/page` (12,019 B → 6,507 B).
- A guard that reads compiled stylesheets no longer passes silently on a sheet that fails to compile: the broken sheet is a finding that quotes the compiler's first line.
- Five shipped guards stop flagging correct code: a function the file binds itself named `confirm`, `fetch` or `setInterval`; reading the browser's zone with `resolvedOptions()`; and a combobox `role="option"` with `tabIndex={-1}`.
- The `image-dimensions`, `semantic-interactive` and `untranslated-string` guards now read components under `apps/*/shared/`, and `raw-motion` reads custom properties. Refresh a guard with `x g guard <name> --force`.

### Fixed

- `@ultimat3/core`: an island that throws an app code no longer carries the framework's error titles. `defineError` is now exported from `@ultimat3/core/page`, the one light browser entry; from the barrel, any import retains both anchored titles tables (`core-error-codes.ts`, `schema-error-codes.ts`). Measured (Bun 1.4.4, minified, one declaration thrown): 12,019 B through `@ultimat3/core`, 6,507 B through `@ultimat3/core/page`. `define-error-bytes.test.ts` pins the island at no table and under 7,168 B. The whole `./page` entry is now 35,150 B, up from 32,707 B (ceiling 35,840 B). `defineError` also no longer throws at module load in a browser without `Error.captureStackTrace`, such as Firefox before 136. The scaffolded `error-declared` guard refuses `defineError` imported from the barrel (`X_ERROR_DECLARED`; refresh it with `x g guard error-declared --force`), and the files `x new` and `x g` write (a slice's `errors.ts`, the domain package) now import it from `@ultimat3/core/page`. An app that added `/* @__PURE__ */` or `"sideEffects": false` to keep the table out can stop relying on them for that: switch the import instead. `/* @__PURE__ */` still drops each declaration an island never throws, about 50 B apiece.
- `@ultimat3/cli` `bare-error` guard: its `fix:` told an app to declare the failure with `defineError` "from @ultimat3/core", the barrel the refreshed `error-declared` guard refuses. It now names `@ultimat3/core/page`, so following one guard's fix no longer trips the other. An app picks the fix up with `x g guard bare-error --force`.
- `@ultimat3/cli` `native-confirm`, `raw-fetch` and `raw-interval` guards: a bare `confirm(`, `fetch(` or `setInterval(` in a file that binds that name itself is the file's own function and no longer a finding. A binding is a declaration, an import, a parameter or a destructured name; `const confirm = async () => {}; void confirm();` was reported as the browser dialog. `window.`, `self.` and `globalThis.` calls are still findings. An app picks the fix up with `x g guard <name> --force`.
- `@ultimat3/cli` `unzoned-date` guard: `Intl.DateTimeFormat().resolvedOptions().timeZone` is no longer a finding. It reads the host's zone and formats no date. An `Intl.DateTimeFormat` that calls `.format(` or `.formatToParts(` with no `timeZone` still is. An app picks the fix up with `x g guard unzoned-date --force`.
- `@ultimat3/cli` `semantic-interactive` guard: a `role="option"` element with `tabIndex={-1}` is no longer `X_SEMANTIC_INTERACTIVE`. That is an option of an `aria-activedescendant` combobox, where the input keeps focus and handles the keys. A clickable inert element, a `role="button"` with no key handler and an option that takes focus are still findings. An app picks the fix up with `x g guard semantic-interactive --force`.
- `@ultimat3/cli` `image-dimensions`, `semantic-interactive` and `untranslated-string` guards: components under `apps/*/shared/` are now read. The guards scanned only `apps/*/{site,app}` and `packages/*/src`, so `<img src="/a.png" alt="" />` in `apps/web/shared/x.tsx` was green. An app picks the fix up with `x g guard <name> --force`, and may then see findings in `shared/` that were always there.
- `@ultimat3/cli` `raw-motion` guard: a raw duration or `cubic-bezier()` assigned to a custom property (`--my-ease: cubic-bezier(0, 0, 1, 1)`) is now `X_RAW_MOTION`. Each `var(--my-ease)` was a second motion scale the guard never saw. The fix writes the token interpolated, `--my-ease: #{tokens.easing(out)}`. An app picks the fix up with `x g guard raw-motion --force`.
- `@ultimat3/cli` `undeclared-custom-property` and `undefined-style-class` guards: a stylesheet that does not compile is now a finding, not a silent pass. One broken sheet made `undeclared-custom-property` report nothing for the whole app, and `undefined-style-class` skipped every class read off a sheet that failed to compile or did not exist. The finding quotes the compiler's first line, read through the new optional `GuardSources.compileError(path)`. `compiled(path)` still answers `undefined` for a broken sheet, so a guard an app wrote against it is unchanged. While any sheet fails, `undeclared-custom-property` reports only the broken sheets and judges their reads once they compile. An app picks the fix up with `x g guard <name> --force`.
