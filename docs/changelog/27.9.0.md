## 27.9.0 - 2026-10-11

### Added

Tier 2 — http. Tier 4 — ai.

- **Provider prompt caching: an `agent()` no longer pays input price for its stable prefix on every turn.** Every turn re-sends the whole transcript, and nothing asked a provider to cache it. A `GenerateRequest` now takes `system: { stable, run }` (two blocks; the stable one first and byte-identical across runs) and `promptCache: { session? }`, and each provider marks the stable system part and the transcript's tail the way its wire and host want — `PROMPT_CACHE_RULES` in `@ultimat3/ai`, a table, sources quoted in `prompt-cache.ts`: `cache_control: { type: 'ephemeral' }` on Anthropic content blocks (three of the four breakpoints), the same mark on content parts for an `anthropic/…` model on OpenRouter (two), and **no** mark for any other model there or on OpenAI, where caching is implicit and an explicit mark on Gemini is a paid write. A session key travels as OpenRouter's `x-session-id` header or OpenAI's `prompt_cache_key`; an endpoint the table does not name is sent nothing. `agent({ system, promptCache })` and `llm({ promptCache })` are the declaration's side: `'auto' | 'off' | { session }`, and `system()` returns the text loaded at run time as `{ stable?, run? }`.
- **Default: `agent()` caches (`promptCache: 'auto'`), `llm()` does not (`'off'`).** This is the one behaviour that changes for a caller who passes nothing: an agent's requests to an Anthropic model now carry `cache_control` marks (so `system` is sent as blocks or parts, not a string), a first turn is billed as a cache write (1.25x input on Anthropic) and later turns as reads, and the pre-flight cost estimate prices the prompt as a write **where a provider serving the model would mark the request** (`Provider.marksPromptCache`), at the dearer of the write and input rates — so a `budget.costPerCall` set within 25% of an agent's prompt cost now refuses for an Anthropic model, and is unchanged for Gemini, OpenAI and any endpoint the table does not name. `promptCache: 'off'` restores the old request byte for byte. A one-shot `llm()` is unchanged. A mark is never put on an empty or whitespace-only text block, and marks a raw request already carries count against the vendor's four first. A session key over 64 characters is sent to OpenAI as a hash of itself; OpenRouter's header takes up to 256 and refuses more.
- **Cache usage is reported per turn and per run.** The chat-completions reader takes `prompt_tokens_details.cache_write_tokens` as well as `cached_tokens` out of `prompt_tokens` (which includes both) and reports them as `cacheWriteTokens` / `cacheReadTokens`; it reported a write as full-price input before. `onTurn`'s event gains `run` — the running `usage` and `cost`, priced once from the summed usage — and the `agent.turn` span event gains `llm.cache.read_tokens` / `llm.cache.write_tokens`. Prices are the model row's existing `cacheReadPerMillion` / `cacheWritePerMillion`; a token budget counts read and written tokens one for one, as it always has.
- **`maxRepeatedToolCalls` — an agent that repeats itself is stopped (`X_AGENT_TOOL_LOOP`, 500).** A cycle of one to three tool turns — the same calls, arguments, results and failures — gone round that many times ends the run: the same turn over and over, or A,B,A,B…. **Default 3, on for every agent**: a loop that used to end in `X_AGENT_MAX_TURNS` or `X_AI_BUDGET_EXCEEDED` after repeating itself now ends earlier with this code. A polled tool whose answer changes is not a repeat; a repair turn neither counts nor resets. Registered `terminal`, so an `agentJob()` dead-letters it on the first attempt.
- **`deadlineMs` — a wall-clock ceiling for one agent run (`X_AGENT_DEADLINE`, 504).** No default. Passing it aborts the model call in flight on its socket, fires every running tool's own `ctx.signal`, and starts no further turn. A tool that ignores its signal is no longer waited for but still runs to its end. Registered `terminal` for jobs.
- `@ultimat3/ai` exports `PROMPT_CACHE_RULES`, `promptCacheRule`, `systemText`, `SESSION_KEY_MAX`, `OPENAI_CACHE_KEY_MAX`, `AgentToolLoopError`, `AgentDeadlineError` and the types `SystemPrompt`, `SystemParts`, `PromptCacheHint`, `PromptCacheOption`, `PromptCacheRule`, `CacheWire`, `AgentSystem`, `AgentRunUsage`.
Tier 0 — core. Tier 1 — seo. Tier 4 — render. Tier 5 — cli.

- **`seo.sitemap.sections` — a sitemap index with named, paginated sections, by configuration.** `/sitemap.xml` was one `<urlset>` until a site passed 50,000 URLs. `seo: { sitemap: { pageSize: 1000, sections: [{ name: 'blog', match: '/blog/**' }, { name: 'ciudades', match: '/juzgados/**' }] } }` makes it a `<sitemapindex>` of `/sitemaps/pages-1.xml`, `/sitemaps/blog-1.xml`, `/sitemaps/blog-2.xml`, …, each a valid urlset; a page no section matches goes to the reserved `pages`. `match` is a path pattern or a list (`/precios`, `/blog/*`, `/blog/**`), read against the path without its locale prefix, so a page and its locale copies share a file; the first section that matches wins. Inside a section pages are sorted by path — the bytes depend on which pages exist, not on the order a query returned them — files are numbered from 1, a section with nothing in it writes no file, and the index `<lastmod>` of a child is the newest `<lastmod>` inside it. The web role serves every child from the route it already had (`GET /sitemaps/:file`, `application/xml`, `public, max-age=3600`, from the same hourly answer as the index — a refresh that fails keeps the previous index and its children together), the static export writes the same files, and `robots.txt` still names `/sitemap.xml` alone. A `name` that is not a lower-case slug, a duplicate, `pages`, a `match` that is not a path pattern or a `pageSize` outside 1–50,000 is `X_CONFIG_INVALID` at boot. **With no `sections` the output is byte-for-byte what it was** (`sitemap-sections.test.ts` pins the hash). [SEO → Sections](https://github.com/developerz-ai/ultimate/wiki/SEO#sections-an-index-by-configuration).
- **`prerender()` may say when a page changed and which locales list it.** Beside a bare string and a params object, an item may be an entry: `{ params: { slug }, lastmod: row.updatedAt, locales: ['es-co'] }` (`PrerenderEntry`; the three forms mix). `lastmod` — a `Date`, or ISO 8601 with an explicit zone — is that page's sitemap `<lastmod>`, written as W3C Datetime in UTC and winning over `seo.sitemap.lastmod`. A time with no zone or free text is the new `X_SITEMAP_ENTRY_INVALID`, naming the route file, never a date read in the server's zone; a moment in the future is clamped to now (refusing it would fail the whole sitemap for one row from a clock a second ahead; writing it is a date a crawler stops trusting). `locales` lists the page — one `<url>` each, hreflang among those only, `x-default` only when the default locale is one of them — in the named locales; `[]` lists it nowhere; a name the app does not route is `X_SITEMAP_ENTRY_INVALID`. A route with no params may answer one entry (`[{ params: {}, lastmod, locales }]`), which is how a page with a `load` says either. The BUILD is unchanged: every routed locale's document is still rendered, and `enumeratePrerender()` still answers params. An entry key outside the three, a `lastmod` that is neither a string nor a `Date`, or `locales` that is not a list of names is `X_PRERENDER_FAILED`. The static export still lists only the pages it emitted (`pagesFor`) and now asks `prerender()` once more for what each says of itself.
- **The scaffolded `apps/web/prerender.ts` writes the SEO files through `writeSiteSeo(out, seo)`.** Nothing to change in an existing app: a `prerender.ts` that loops over `seo.sitemaps` itself already writes an index and its parts.
- New names: `SitemapSectionConfig`, `SITEMAP_DEFAULT_SECTION`, `SITEMAP_PAGE_SIZE_MAX`, `sectionPatterns`, `sitemapSectionIssues` (`@ultimat3/core`; `SeoSitemapConfig` gains `sections` and `pageSize`); `SitemapPage`, `SitemapSection`, `expandRoutePages`, `sectionOf`, `sitemapDatetime`, `disallowMatcher`, `SITEMAP_MAX_BYTES`, `sitemapEntryInvalid`, `RouteRecord.locales`, `SitemapFile.lastmod`, and `sections` / `maxBytes` / `disallow` / `now` on `buildSitemap` (`@ultimat3/seo`); `PrerenderEntry`, `PrerenderItem` (`@ultimat3/render`) and `enumeratePrerenderEntries` (`@ultimat3/render/server`); `writeSiteSeo`, `SiteSeoSitemap` (`@ultimat3/cli`). `PrerenderFn`'s return type is wider; code that only declares a `prerender` is unaffected, code that reads one's result itself should call `enumeratePrerender`.

### Fixed

Tier 4 — ai.

- **A caller that goes away during an agent's model call is `X_ABORTED`.** The aborted socket surfaced as `X_AI_PROVIDER_UNAVAILABLE`, which the package classifies `retryable`, so an HTTP client was told to come back for a run it had itself abandoned. `X_ABORTED` is core's and unclassified: it reads `terminal` on the wire, and in a job the attempt count still decides — nothing about a drain or an attempt timeout changes, jobs settles those off its own signal.
Tier 1 — seo. Tier 5 — cli.

- **A page that is `noindex` in one locale is no longer listed — or cross-linked — in that locale.** The sitemap read each route's `meta` once, in no locale, and emitted one `<url>` per routed locale: a page whose `meta` answers `robots: { index: false }` for English only was listed at `/en/…`, and every other copy's hreflang pointed at it ("alternate page with noindex"). `meta` is now read once per routed locale; the page is listed in the locales that may be indexed and its cluster names only those. As before, this reads a route with no params and no `load` — a dynamic page says it with `locales` on its `prerender()` entry.
- **A URL `seo.robots.disallow` blocks is no longer in the sitemap.** `robots.txt` and the sitemap are written from one config, and the sitemap listed URLs the other told crawlers not to fetch ("submitted URL blocked by robots.txt"). A rule is read as a crawler reads it — a prefix, `*`, a trailing `$`; a locale copy it blocks leaves its hreflang cluster. An app whose sitemap shrinks on upgrade was listing a blocked page: narrow the rule to keep it.
- **A sitemap file past 50 MB is split.** Only the 50,000-URL cap was enforced; a site with many locales (every `<url>` carries the whole hreflang cluster) could pass the protocol's 50 MB uncompressed limit below it, which a crawler answers with "sitemap could not be read". Sections and the unsectioned split both cut on bytes now (`SITEMAP_MAX_BYTES`).
