## 27.8.1 - 2026-10-11

### Fixed

Tier 2 — http. Tier 4 — render. Tier 5 — cli.

- **A withdrawn `isr` page is down at every spelling of its URL.** The store key was the request's raw pathname, and the router matches a normalised one. `/blog//abc` and `//blog/abc` were answered with the page (200) and stored under a key the route table could not read back, so the entry had no `ttl` and no tags: `s-maxage=60` with a day of `stale-while-revalidate`, no `Surrogate-Key`, and no bust reached it — under `onInvalidate: 'purge'` a withdrawn article stayed readable there, at the origin and at the edge, for the life of the process. The key is now the address the router **matched** (`ctx.routePath`, set by the `context` stage from the string it handed the route table), spelled by `@ultimat3/http`'s new `canonicalPath`, which is built from the functions the router segments and decodes a request with (`route-path.ts`) — one normalisation, not two. Every spelling carries its route's `ttl`, purge keys and `canonical`, and a bust (`'stale'` or `'purge'`) reaches it. No status changes and nothing is redirected. An app with a withdrawn page should upgrade and restart: entries stored under the old keys live in the process.
- **One `isr` entry per page, however the URL is written.** `/blog/%61bc`, `/blog/abc/`, `/blog/caf%c3%a9` versus `%C3%A9`, and `/blog/abc` were each a render and an entry — a 20-letter slug has a million percent-encodings, against a store of 1,000 that evicts the least recently generated — and each stored document named its own spelling as `canonical`. All are the `/blog/abc` entry now, and `load`, `meta` and the page receive that address as `url`. An encoded slash is never decoded into a separator: `/blog/a%2fb` is the `/blog/a%2Fb` entry (`slug` is `a/b`), and `/blog/a/b` is still a 404 for `/blog/[slug]`. A locale's home is `/en/` for `/en` and `/en/` alike.
- **A key no route owns is never stored.** `isrController().serve()` and `.regenerate()` render it for the request that asked (`private, no-store`, logged once as `isr.key.unowned`) instead of storing an entry with the defaults — no `ttl`, no tags — that nothing could invalidate; a copy an earlier release left under such a key in a shared store is deleted when asked for, not served. The served pipeline also answers uncached a request whose key reads back as a DIFFERENT route than the one the router matched (`//en/x` is the `/[lang]/x` route, and its address is the English `/x` page's). **If you call `isrController` yourself** with keys that match no registered route, those pages are no longer cached: key on `isrKey(url, locale)` for a URL a route owns.
- **`isr` under a `basePath` honours `revalidate`.** The key kept the mount (`/shop/blog/a`), which the route table has never heard of, so under any `basePath` every `isr` page matched no route: the declared `ttl` and `tags` were ignored and no bust reached anything. The key carries no base path now; the `url` a page receives still does.
- **A served `static` page is one kept document.** The container's static memo (1,024 documents) was keyed on the raw pathname too, so `/about/`, `//about`, `/about//`, … were each a render and a slot, and a visitor could fill it before the real pages arrived — each of which was then rendered per request for the life of the process. It is keyed, and the page rendered, at the matched address, as the export writes it. `ssr` and `stream` pages still receive the URL as the visitor wrote it.
- `@ultimat3/http` exports `canonicalPath`, `requestAddress(ctx)` and `RequestAddress`; `RequestContext` gains `routePath`. `@ultimat3/render/server` exports `isrRouteFor`. `isrKey(url, locale)` canonicalises the pathname it is given, so a caller's own keys change spelling only where the URL was not already canonical.
